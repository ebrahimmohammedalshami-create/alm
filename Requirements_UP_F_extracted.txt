SCREENING DATA POINTS REQUIRED: 
1. Source System 
Required / Optional: Required
What to provide: Upstream system sending the screening request, such as CBS, 
MMS, LOS, API, or UI.
2. Channel 
Required / Optional: Required
What to provide: Business journey where screening is triggered, such as 
ONBOARDING, PERIODIC_REVIEW, or TRANSACTION.
3. Institution ID 
Required / Optional: Required
What to provide: Client/institution code under which screening should be 
performed.
4. Entity Type 
Required / Optional: Required
What to provide: Type of entity being screened, such as ORGANIZATION, 
MERCHANT, LIMITED_LIABILITY_COMPANY , NPO_NGO.
5. Entity Relation 
Required / Optional: Required
What to provide: Role of the entity, such as CUSTOMER, DIRECTOR, POC, or 
AUTHORIZED_SIGNATORY .
6. External Entity ID 
Required / Optional: Required for primary screening
What to provide: Unique entity/customer ID from the client’s source system.


--- PAGE 3 ---
7. Primary Entity ID 
Required / Optional: Required for secondary screening
What to provide: ID of the already-screened primary entity under which related 
entities are screened.
8. Relation Entity ID 
Required / Optional: Optional
What to provide: Client-side ID for a related entity, such as director ID, POC ID, or 
signatory ID.
9. Name 
Required / Optional: Required
What to provide: Legal name or full name of the person, merchant, organization, or 
related party.
10. Date of Birth 
Required / Optional: Required for individuals/related persons
What to provide: Date of birth for individuals or related persons, preferably in 
YYYY-MM-DD format.
11. Country / Nationality 
Required / Optional: Required
What to provide: Country, nationality, residence country, or incorporation country, 
preferably ISO alpha-2 code like IN, US, AE.
12. Address 
Required / Optional: Optional but recommended
What to provide: Residential, registered, or operating address used as supporting 
screening evidence.
13. Gender 
Required / Optional: Optional
What to provide: Gender of the individual, such as MALE or FEMALE, when 
available.
14. Entity Sub Type 
Required / Optional: Optional
What to provide: More speciﬁc organization category, such as LLC, joint venture, 
NGO, or government body.
15. Identiﬁcation Type 1 
Required / Optional: Required
What to provide: Primary identiﬁcation document type, such as PASSPORT, 
NATIONAL_ID, REGISTRATION_ID, TAX_ID, or OTHER.
16. Identiﬁcation Number 1 

--- PAGE 4 ---
Required / Optional: Required
What to provide: Primary identiﬁcation document number/value.
17. Identiﬁcation Type 2 
Required / Optional: Optional
What to provide: Second identiﬁcation document type, if available.
18. Identiﬁcation Number 2 
Required / Optional: Optional
What to provide: Second identiﬁcation document number/value, if available.
19. Identiﬁcation Type 3 
Required / Optional: Optional
What to provide: Third identiﬁcation document type, if available.
20. Identiﬁcation Number 3 
Required / Optional: Optional
What to provide: Third identiﬁcation document number/value, if available.
21. Phone Number 
Required / Optional: Optional
What to provide: Phone number associated with the entity or related person.
22. Email 
Required / Optional: Optional
What to provide: Email address associated with the entity or related person.
23. Metadata 
Required / Optional: Optional
What to provide: Additional client-side context such as batch ID, branch ID, user 
ID, workﬂow ID, or session ID.
24. Client Request ID 
Required / Optional: Required for S2S/API
What to provide: Client-generated unique request reference used for status 
lookup, reconciliation, and idempotent tracking.

Client Conﬁguration Needed
Configuration What Client Should Provide
Supported transaction modesSYNC, ASYNC, or BOTH
Supported channels Example: ATM, POS, ECOM
Callback/webhook URL Endpoint where EFRM should send async decisions and case updates
Webhook authentication 
method API key, bearer token, mTLS, or signed payload
Decision mapping How client maps ALLOW, BLOCK, REVIEW, STEPUP internally
Response code mapping Client-specific codes for allow/block/review/step-up
Step-up method OTP, PIN, biometric, device challenge, or other method
Case/alert preference Whether EFRM should auto-create alerts/cases for block/review decisions
Retry policy Number of webhook retries and retry interval
Timeout policy Maximum wait time for webhook acknowledgement
